HadyanCode configuration lives in two scopes:

- **Global configuration** in `~/.hadyancode/` (applies globally across all HadyanCode applications, including IDE, CLI, and SDK)
- **Project configuration** in `.hadyancode/` (applies only to the current workspace)

## Configuration Directory Layout

HadyanCode stores shared configuration across a few well-known locations. The primary root is `~/.hadyancode/`, with structured app state under `~/.hadyancode/data/`:

```text
~/.hadyancode/
  data/
    settings/
      providers.json           # API keys and provider configuration
      global-settings.json     # Global settings
      hadyancode_mcp_settings.json  # MCP settings
    teams/                     # Team state
    sessions/                  # Session data
    db/                        # SQLite databases (for example cron.db)
    workflows/                 # Global workflows
  rules/                       # Global rules
  hooks/                       # Global hooks
  skills/                      # Global skills
  agents/                      # Global agent definitions
  plugins/                     # Global plugins (.js, .ts)
  cron/                        # Global cron specs
```

Additional global search paths supported by the code:

```text
~/Documents/HadyanCode/
  Rules/                       # Additional global rules
  Hooks/                       # Additional global hooks
  Plugins/                     # Additional global plugins
  Workflows/                   # Additional global workflows
```

Project-level configuration lives in `.hadyancode/` at your repository root:

```text
.hadyancode/
  rules/                       # Project rules
  skills/                      # Project skills
  hooks/                       # Lifecycle hooks
  agents/                      # Project agent definitions
  plugins/                     # Project plugins
  cron/                        # Workspace cron specs
```

Notes:

- Global provider settings, global settings, and MCP settings are stored under `~/.hadyancode/data/settings/`.
- Global workflows resolve from `~/.hadyancode/data/workflows/`.
- Global rules, hooks, skills, agents, plugins, and cron specs resolve directly under `~/.hadyancode/`.
- Rules, hooks, plugins, and workflows may also be discovered from `~/Documents/HadyanCode/` for compatibility.

## What Goes Where?

- Use **global (`~/.hadyancode/`)** for defaults shared across all HadyanCode applications (IDE, CLI, SDK) on your machine.
- Use **project (`.hadyancode/`)** for team-shared behavior that should travel with the repo.

Commit `.hadyancode/` files you want to share with your team. Keep secrets out of the repo.

## Configure Through the CLI

Use the interactive config UI:

```bash
hadyancode config
```

From there, you can view/edit:

- Settings (global + workspace)
- Rules
- Skills
- Hooks

## Useful Configuration Commands

Use a custom configuration directory:

```bash
hadyancode --config /path/to/custom/config "your task"
```

Or via environment variable:

```bash
export HADYANCODE_DATA_DIR=/custom/path/to/hadyancode
hadyancode "your task"
```

View CLI logs when troubleshooting:

```bash
hadyancode dev log
```

## Environment Variables

| Variable | Description |
|----------|-------------|
| `HADYANCODE_DATA_DIR` | Custom data directory (replaces `~/.hadyancode/data/`) |
| `HADYANCODE_HUB_ADDRESS` | Override hub address (default: `127.0.0.1:25463`) |
| `HADYANCODE_SESSION_BACKEND_MODE` | Force backend mode (`local`, `hub`, `remote`, `auto`) |
| `HADYANCODE_SANDBOX` | Enable sandbox mode |
| `HADYANCODE_SANDBOX_DATA_DIR` | Sandbox session storage directory |
| `HADYANCODE_HOOKS_DIR` | Additional hooks directory |
| `HADYANCODE_COMMAND_PERMISSIONS` | JSON policy restricting shell commands |

### HADYANCODE_DATA_DIR

```bash
export HADYANCODE_DATA_DIR=/custom/path/to/hadyancode
hadyancode "your task"
```

### HADYANCODE_COMMAND_PERMISSIONS

Restrict which shell commands HadyanCode can execute:

```bash
export HADYANCODE_COMMAND_PERMISSIONS='{"allow": ["npm *", "git *"], "deny": ["rm -rf *"]}'
```

Format:

```json
{
  "allow": ["pattern1", "pattern2"],
  "deny": ["pattern3"],
  "allowRedirects": true
}
```

Rules:

- `deny` overrides `allow`
- If `allow` is set, commands not matching `allow` are denied
- `allowRedirects` controls shell redirects (`>`, `>>`, `<`), default `false`

## Security Notes

<Warning>
Only use rules, hooks, skills, and plugins from sources you trust.
</Warning>

Hooks and plugins can execute code. Review them like any other executable artifact before adding them globally or to a project.
